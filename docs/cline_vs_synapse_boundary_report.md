## 3. The 7-Level Tool Precedence Hierarchy

Every tool request generated by Cline must successfully traverse all 7 precedence levels in Synapse before an execution token is granted:

1. **Precedence Level 0: Tenant Context Validation**  
   Strict isolation boundary check. Validates `tenantId` is non-empty and workspace paths resolve within the tenant root.
2. **Precedence Level 1: Emergency Kill Switch Evaluation**  
   Evaluates Level 1 (stream abort), Level 2 (session stop), Level 3 (process kill & filesystem lock), and Level 4 (global halt).
3. **Precedence Level 2: Human Approval & Escalation**  
   Escalates high-risk operations to human operators; rejects operations without required approvals.
4. **Precedence Level 3: Policy & Workspace Sandbox Boundaries**  
   Enforces file path normalization and forbids path traversal (`../`) or escaping the configured workspace root.
5. **Precedence Level 4: Agent Role Capabilities**  
   Checks that the calling `agentId` holds the explicit capability for `toolName` in the `AgentRegistry`.
6. **Precedence Level 5: Risk Ceiling & Blast Radius**  
   Calculates blast radius; blocks tools exceeding the maximum allowable impact score.
7. **Precedence Level 6: Dynamic Behavioral Rate Limits**  
   Enforces per-minute invocation thresholds to prevent resource exhaustion or runaway loops.

## 4. Boundary Verification in Runtime

During live closed-loop acceptance:
- Cline autonomously called `submit_execution_plan`, `simulate_execution_branch`, and `propose_replan`.
- Synapse intercepted all 3 calls, applied OCC concurrency checks, spawned isolated simulation twins without production mutation, and produced immutable versioned DAGs.
- No direct tool bypass occurred: all physical executions required HMAC-signed tokens matching the tool parameter SHA-256 hash.
