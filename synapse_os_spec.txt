SYNAPSE OS — FINAL BACKEND ARCHITECTURE
0. The fundamental decision
We are building:
Synapse OS = a governed agent operating system built by forking Cline and embedding Cline's runtime as its native execution engine.
Not:
Synapse
   ↓
external Cline CLI
Not:
Synapse
   ↓
Cline npm package
And definitely not:
Synapse
 ├── Cline
 ├── Codex
 ├── Claude Code
 ├── Aider
 └── other engines
Instead:
                         SYNAPSE OS
                             │
              ┌──────────────┴──────────────┐
              │                             │
       SYNAPSE CONTROL PLANE          SYNAPSE WORLD
              │                         ENGINE
              │                             │
              ▼                             │
        FORKED CLINE ENGINE ◄───────────────┘
              │
     ┌────────┼───────────────┐
     │        │               │
   Agent    Teams           Tools
     │        │               │
     └────────┼───────────────┘
              │
        Runtime / Workspace
              │
              ▼
          Real World
Cline is the execution substrate.
Synapse becomes the:
control plane 
governance layer 
safety layer 
verification layer 
observability layer 
multi-tenant layer 
agent management layer 
simulation/digital-twin layer 
external-agent supervision layer 
orchestration layer.

39. Cline CLI
Because we're forking the repository, the CLI is no longer something the customer installs.
It becomes an internal capability.
Cline's CLI currently exposes commands including mcp, dev, doctor, history, hook, plugin, schedule, hub, update, version, and kanban. 
We should therefore preserve the useful Cline capabilities in the fork, but Synapse's backend decides when/how they are exposed.
For example:
Cline CLI
    ↓
Synapse Runtime
    ↓
Synapse Policy
    ↓
Cline execution
not:
User → arbitrary shell → Cline
40. Cline Kanban
Same principle.
Don't make a completely separate Synapse execution system just because Cline has a Kanban application.
Cline's CLI itself currently exposes kanban. 
Synapse should instead treat Kanban as:
Synapse Task
      ↓
Cline Session / Team
      ↓
Cline task execution
      ↓
Synapse events
      ↓
Synapse verification
Later the Synapse frontend can provide the superior Kanban UI.
